# Поиск максимального значения в большом массиве данных

## Описание проекта

В рамках проекта реализована программа на Go, демонстрирующая использование многопоточности для ускорения обработки больших объёмов данных.

Программа генерирует массив случайных положительных чисел и сравнивает два способа поиска максимального элемента:

- последовательный поиск в одном потоке;
- параллельный поиск с использованием 8 горутин.

Также измеряется время выполнения каждого алгоритма, что позволяет оценить прирост производительности при использовании многопоточности.

---

## Реализованный функционал

### Генерация данных

Реализована функция `generateRandomElements()`, которая:

- создаёт слайс заданного размера;
- заполняет его случайными положительными числами;
- корректно обрабатывает граничные случаи (например, размер массива равен 0).

### Последовательный поиск максимума

Реализована функция `maximum()`, которая:

- принимает слайс целых чисел;
- находит максимальный элемент последовательным перебором;
- обрабатывает пустой слайс и другие граничные случаи без возникновения паники.

### Параллельный поиск максимума

Реализована функция `maxChunks()`, использующая многопоточность.

Алгоритм работы:

1. Исходный слайс разделяется на 8 частей.
2. Для каждой части запускается отдельная горутина.
3. Каждая горутина вычисляет максимум своего участка.
4. Полученные локальные максимумы сохраняются в отдельный слайс.
5. После завершения всех горутин определяется максимальное значение среди найденных максимумов.

Для синхронизации работы горутин используется `sync.WaitGroup`.

---

## Тестирование

Для основных функций написаны unit-тесты.

Проверяются следующие сценарии:

- пустой слайс;
- слайс с одним элементом;
- слайс с несколькими элементами;
- корректность генерации случайных данных;
- корректность поиска максимального значения.

---

## Измерение производительности

Для сравнения эффективности алгоритмов используется пакет `time`.

Измеряется время выполнения:

- последовательного поиска максимума;
- многопоточного поиска максимума.

Результаты выводятся в микросекундах, что позволяет сравнить скорость работы обоих подходов на больших массивах данных.
